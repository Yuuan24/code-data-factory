# Code Data Factory

面向 Agent 工具调用轨迹的数据工程项目：以信息查询、计算、单位与时间转换助手为具体场景，
生产可执行任务和完整交互轨迹，治理质量、去重、污染与谱系，以评测反馈驱动数据选择，并用
固定条件训练实验测量数据价值。优先复用开源组件，项目工作集中于数据语义、质量和归因。

## 当前状态

**规格与计划已于 2026-09-08 迁移为 2.0，尚未开始实现。任务清单已按新版重新生成。** 本仓库当前发布的是项目规格、架构计划、数据/命令契约、研究决策和
证据治理规则；尚未发布可运行的数据流水线、安全执行环境、Ray 多节点运行或训练实验结果。

因此，仓库不会宣称以下成果已经成立：

- 真实隔离执行或 1/2/4 节点 Ray Data 运行；
- 任何数据配方带来的模型能力提升；
- 生产级规模、可用性或组织级平台能力。

每项未来结论都必须附带对应的原始产物、复现入口、限制和证据层级。完整的当前边界见
[证据日志](docs/evidence-journal.md)。

## 项目要解决什么

普通清洗流程只能说明“数据被处理过”，不能说明样本是否可追溯、是否真的通过隔离执行验证，或
某种数据决策是否对模型产生可归因的影响。本项目将这些问题组织成一条可审计的数据闭环：

```text
公开轨迹 / 冻结资料与任务
  -> 来源、许可与敏感信息治理
  -> 可执行任务与完整轨迹生产、质量/去重/污染控制
  -> 交互完整性、跨步骤依赖与独立结果验证
  -> 不可变数据版本、数据卡与双向谱系
  -> 逐项评测发现
  -> 专项数据动作与复验
  -> 固定预算的处理组/对照组测量
  -> 可定位的证据、负结果与复现记录
```

第一版运行于 Linux，处理文本与结构化工具轨迹。Ray Data 是分布式数据处理库，用于批处理及
性能/稳定性验证；监督微调（supervised fine-tuning，SFT）是下游数据价值测量。
后续强化学习（reinforcement learning，RL）接入和长程稀疏奖励扩展是首版必须验收的设计要求：
真实采样适配、32/128 步契约、上下文与受控恢复、独立奖励记录；正式 RL 优化属于后续阶段。

## 设计范围

| 方向 | 首版计划 | 不在首版范围内 |
|---|---|---|
| 数据生产与治理 | 来源审计、轨迹规范化、质量/重复/污染、分类采样与不可变发布 | 无界采集、多模态处理、反爬 |
| 批处理与稳定性 | 本地/Ray 等价、真实 1/2/4 节点、幂等与故障恢复 | 第二套计算引擎、存储内核 |
| 交互验证 | 参数/依赖/结果/证据检查、未知判定与失败保留 | 通用环境或在线服务平台 |
| 反馈与归因 | 开发短板→数据动作→固定条件 SFT→实际复评 | 超参数搜索、自训练算法研究 |
| 后续扩展 | 一个 RL 训练器采样适配、长程/稀疏奖励契约和回执 | 首版正式 RL 优化、长程模型能力收益实验 |

真实多节点、隔离执行和训练依赖均不可用时，结论必须保持为软件级验证或未验证，不能以测试、
计划或外部论文替代。

## 证据标准

| 证据层级 | 可以证明什么 | 不能证明什么 |
|---|---|---|
| `UNVERIFIED` | 问题、设计、假设和计划 | 已实现功能或实验结果 |
| `SOFTWARE_VALIDATED` | 代码、静态检查、自动化测试或模拟流程 | 隔离执行安全性或模型收益 |
| `EXECUTION_VALIDATED` | 真实、隔离、受限环境中的执行结果 | 模型能力提升 |
| `TRAINING_EVIDENCED` | 公平对照下的真实参数更新、评测和完整谱系 | 超出实验范围的泛化结论 |

有关公平归因、谱系、负结果保留和失败关闭的完整规范，请阅读
[项目宪章](.specify/memory/constitution.md)。

## 计划中的交付顺序

1. 核查公开数据、构建 100 个可执行先导任务，并完成开源组件兼容门禁。
2. 生产与治理完整轨迹，完成质量、去重、污染、分组切分和增量发布。
3. 验证训练器采样适配、长程数据与恢复契约，以及真实 Ray 多节点处理。
4. 运行开发评测，构建反馈驱动数据配方和同池匹配对照。
5. 在训练方法、预算和输入冻结后，完成两配方三个种子的 SFT 与真实交互评测。
6. 保留全部结果，复现代表性流程并审计归因证据。

当前阶段与验收以 [实施计划](specs/001-code-data-factory/plan.md) 为准；具体实现按 [新版任务清单](specs/001-code-data-factory/tasks.md) 执行。
