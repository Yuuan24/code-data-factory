# Code Data Factory

面向代码训练数据的数据工程项目：从许可明确的有界代码来源构建可追踪的数据版本，治理质量、
去重、污染和执行证据，并用评测反馈驱动下一轮数据选择。模型训练只用于在固定预算下测量数据
价值，不是本项目的主体。

## 当前状态

**设计完成，尚未开始实现。** 本仓库当前发布的是项目规格、架构计划、数据/命令契约、研究决策和
证据治理规则；尚未发布可运行的数据流水线、安全执行环境、Ray 多节点运行或训练实验结果。

因此，仓库不会宣称以下成果已经成立：

- 真实隔离执行或 1/2/4 节点 Ray Data 运行；
- 任何数据配方带来的模型能力提升；
- 生产级规模、可用性或组织级平台能力。

每项未来结论都必须附带对应的原始产物、复现入口、限制和证据层级。完整的当前边界见
[证据日志](docs/evidence-journal.md)。

## 项目要解决什么

普通清洗流程只能说明“数据被处理过”，不能说明样本是否可追溯、是否真的通过隔离执行验证，或
某种数据决策是否对模型产生可归因的影响。本项目将这些问题组织成一条可审计的数据闭环：

```text
有界代码来源
  -> 来源、许可与敏感信息治理
  -> 任务/候选样本生成与质量、去重、污染控制
  -> 静态检查与隔离执行验证
  -> 不可变数据版本、数据卡与双向谱系
  -> 逐项评测发现
  -> 专项数据动作与复验
  -> 固定预算的处理组/对照组测量
  -> 可定位的证据、负结果与复现记录
```

第一版只聚焦 Python、许可明确的有界来源和必要文本数据。Ray Data 是 Ray 提供的分布式数据处理库；
它用于验证本地与分布式模式是否复用同一业务语义。监督微调（supervised fine-tuning，SFT）仅作为
数据价值的下游测量手段。

## 设计范围

| 方向 | 首版计划 | 不在首版范围内 |
|---|---|---|
| 数据生成与治理 | 来源快照、样本谱系、许可/敏感信息门禁、质量与去重 | 无界互联网采集、多模态数据 |
| 执行验证 | 静态检查、gVisor（基于用户态内核的容器隔离运行时）隔离执行、重复运行与失败关闭 | 在开发机或普通容器中执行不可信代码 |
| 分布式处理 | 本地/Ray 语义等价与真实 1/2/4 节点有界测量 | Ray Train、Ray Tune、Ray Serve 或组织级平台 |
| 反馈闭环 | 从 development（开发）评测发现映射到数据动作并复验 | 在线自动调度平台 |
| 数据价值 | 等有效词元、同池匹配、多种子处理组/对照组 | 持续预训练、强化学习、超参数搜索、模型服务 |

真实多节点、隔离执行和训练依赖均不可用时，结论必须保持为软件级验证或未验证，不能以测试、
计划或外部论文替代。

## 证据标准

| 证据层级 | 可以证明什么 | 不能证明什么 |
|---|---|---|
| `UNVERIFIED` | 问题、设计、假设和计划 | 已实现功能或实验结果 |
| `SOFTWARE_VALIDATED` | 代码、静态检查、自动化测试或模拟流程 | 隔离执行安全性或模型收益 |
| `EXECUTION_VALIDATED` | 真实、隔离、受限环境中的执行结果 | 模型能力提升 |
| `TRAINING_EVIDENCED` | 公平对照下的真实参数更新、评测和完整谱系 | 超出实验范围的泛化结论 |

有关公平归因、谱系、负结果保留和失败关闭的完整规范，请阅读
[项目宪章](.specify/memory/constitution.md)。

## 计划中的交付顺序

1. 建立 Python 项目、版本化契约、许可明确的来源快照和本地数据流水线。
2. 实现质量、去重、污染控制、数据切分和不可变数据发布。
3. 在独立 Linux 主机上验证 gVisor 隔离执行；在真实 Linux 节点上测量 Ray Data。
4. 构建逐项评测、评测发现到数据动作的闭环和同池匹配对照。
5. 仅在训练方法、预算和输入冻结后，运行正式 SFT 对照并发布全部终态结果。
6. 复现代表性流程，发布证据清单与限制说明。

任务的精确依赖、验收产物和停止规则以 [任务清单](specs/001-code-data-factory/tasks.md) 为准。
